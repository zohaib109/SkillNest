# SkillNest implementation roadmap

Work on main. Use the [product specification](pilot-spec.md) for behavior, [operating costs](operating-costs.md) for spending authority and [execution record](execution.md) for completed checks. Each row ends in a usable workflow. Finish locally verifiable work while external launch gates remain open.

| Order | Workflow | Implementation and acceptance |
| --- | --- | --- |
| Foundation | Verified account → approved tutor → held and paid sandbox booking → cancellation review | Preserve the local MongoDB tests for role assignment, moderation, DST, concurrent holds, duplicate capture, late payment and balanced refund reversals. Prior checkpoints are listed in the execution record. Real payment and payout are separate. |
| 1 | Explore a bookable lesson before signup | Opt-in only for public tutors. Check list, direct URL and actual availability against approval and audience. Show duration, exact total and a compatible opening, support narrow screens and same-currency price comparisons. A legacy private tutor still works for verified students. Guest cannot mutate. Exercise opt-out, empty and full weeks, price changes and sign-in return. |
| 2 | Bring a problem and test progress | Add optional goal to the hold. Carry it to the confirmed tutor. Store a recap and small independent exercise, surface learner response and reuse on return. Keep each booking private and idempotent. Prior bookings without notes remain valid. Distinguish learning activity from financial completion. Verify both roles, unrelated users, cancellation, retries and a missing response. |
| 3 | Coordinate and deliver | Booking-linked text with limits, report action, pagination and refresh. Confirmed participants can join within the allowed window via a short-lived token issued by the server. Device test, reconnect, explicit unavailable state, minimal attendance events. Two different browsers, revocation and disconnect tests. RTC account/plan review gating applies independently. |
| 4 | Resolve and settle | Participant incident report, timeline, queue, notification and resolution. Automatic handling only for approved unambiguous policies. Replay-safe compensation entries, receipt, pending earnings, settlement and payout reconciliation. One completed booking permits one student review. Simulate both no-shows, technical failure, double delivery, partial refund, rejected payout and appeal. |
| 5 | Admit real users | Explicit adult eligibility including OAuth/legacy users, final policies, account abuse controls, contact review, retention and deletion, accessible mobile flows, backup restoration, Atlas TLS, Google OAuth, transactional email, provider settlement, realistic two-party video, budget caps and support coverage. Produce a signed-off commercial pilot plan before enrolling paying users. Deployment is separately authorized. |
| After pilot | Improve a measured bottleneck | Test a verified-student private fit question with one tutor if profile/video/30-minute options leave material hesitation. Expand to maths after supply and demand evidence. Defer recurring plans, free live events, document uploads, AI feedback and LMS features. |

For each change run lint, typecheck, unit tests and build. For database work use an isolated replica set and include a verified denial case. Record observed browser behavior separately from unit and integration evidence. Each safe checkpoint should be recoverable from GitHub main.
